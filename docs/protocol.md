# Native HID PID transport

`native/HidPidDevice.cpp` is original code implementing the physical Saitek Cyborg Evo Force interface, USB VID 06A3 / PID FFB5. It does not load the old Saitek DLL or kernel driver. Windows keeps its existing HID input binding.

The transport validates the supplied HID handle's VID/PID, joystick usage, report lengths, report field geometry through the Windows HID parser, and the PID Pool feature. The accepted physical protocol has 300 bytes of parameter RAM, two-byte alignment, and parameter sizes of 1 byte for constant force, 12 for periodic effects, 12 for envelopes, and 8 for each condition axis. Type-specific offsets occupy Ordinal-page usages 1 and 2 in link collection 6. Other pool layouts are rejected.

This is deliberately specific to the observed descriptor. The physical descriptor allows indices 0 through 9 and reports ten simultaneous effects. This implementation conservatively leaves index 0 unused and provides nine slots. It also leaves parameter offset zero unused as an allocation policy; zero is not assumed to be a protocol null pointer for active parameter references. A disabled condition axis has an unused zero offset. The descriptor does not provide a Set Effect block size in its PID Block Size collection. Treating the Set Effect table as separate from the 300-byte parameter pool is a device-specific inference corroborated by the existing exact-device implementation, not a general PID rule.

Constant force, square, sine, triangle, sawtooth-up, sawtooth-down, spring, and damper are encoded. Conditions keep separate X/Y parameter blocks. Per-effect gain and global gain multiply the force parameters and envelope levels once. The hardware Device Gain report is held at its nominal value of 128 to avoid applying global gain twice. Offset and deadband values are geometry and are not gain-scaled.

Every constant or periodic effect owns a 12-byte envelope block and writes it before Set Effect. If the application supplies no envelope, the transport writes zero attack/fade times and levels, preserving the sustain force while providing a valid nonzero envelope reference. The logical `hasEnvelope` flag remains false; unused envelope fields in the application DTO are ignored. Constant effects therefore consume 14 pool bytes including alignment, and periodic effects consume 24. This fixes the previous reference to uninitialized offset zero: the physical offset descriptor has no null state, and the published exact-device implementation initializes an envelope even for an unshaped constant or periodic effect. Explicit envelopes and condition layouts retain their behavior. This encoding correction alone does not establish physical force or simulator acceptance.

Finite DirectInput microseconds round up to the nearest supported millisecond; a positive finite value never turns into a zero or infinite duration. Explicit `INFINITE` duration becomes the HID 0xFFFF sentinel. Finite durations, start delays, and trigger repeat intervals above 65,534 ms are rejected. Envelope times and periodic periods have a 10,000 ms limit from the descriptor. Loop counts support 1..254 and explicit infinity. Button-triggered replay is currently rejected and must not be advertised; this avoids stale triggers referencing freed parameter blocks. Envelope-on-condition effects are rejected.

Download publishes parameter reports followed by Set Effect and never issues Start. A running effect can change force, direction, coefficients, saturation, gain, and envelope values in place when its type, axes, envelope presence, and timing are unchanged. An update that changes those structural fields returns `DIERR_EFFECTPLAYING` before I/O, allowing the COM layer to decide whether a restart was authorized. SetGain only rewrites parameter reports. Stop, free, close, and error paths do not start effects.

The opened HID handle shares read/write access with the simulator. Each output uses overlapped I/O with a 750 ms deadline and a further 750 ms cancellation wait. Any write failure attempts Stop All and Actuators Off, closes the handle, and invalidates all local allocation/playback state. A new Open performs validation and reset; there is no automatic reconnect or effect replay. If Windows has not completed a cancelled request by the cleanup deadline, a module-pinned worker retains its buffer and OVERLAPPED until completion. If that worker cannot be created, those few resources are intentionally retained until process exit rather than released while the kernel could still reference them.

Playback status uses the driver's successful Start/Stop commands and a monotonic timer. Pause freezes that timer; Actuators Off does not. Status is an estimate, not a readback of force being produced. Physical direction, correct force magnitude, and simulator behavior remain open owner acceptance gates described in [the alpha guide](community-alpha.md).

The transport permits Start while actuators are disabled: the effect plays muted and its finite timer still advances. Start itself never sends an actuator-enable command; the COM layer decides whether an explicit playback request should enable the device and preserves the application's explicit OFF intent. Reset clears downloaded effects and pause state, then explicitly disables actuators before restoring nominal device gain. This compensates for physical PID Reset enabling actuators, while DirectInput Reset specifies a disabled startup state. See the [DirectInput command contract](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ee417918(v=vs.85)).

`tests/Run-HidPidTests.ps1` builds and runs pure protocol/allocation tests, an injected transport lifecycle with partial-write/disconnect/timeout failures, and a private named-pipe overlapped-cancellation test. It never opens joystick hardware. The test-only writer interface is excluded from the production DLL build.

Protocol references: [USB HID PID 1.0](https://www.usb.org/document-library/device-class-definition-pid-10), the existing local Windows descriptor/pool observations (raw private captures are not distributed), and the [published exact-device descriptor](https://github.com/zanppa/hid-pidff/tree/37709a8efa76bef8bd82d2b89b478019700ecaff). The GPL implementation was used as behavior evidence, not copied or adapted into this source. The runtime does not load the vendor effect DLL or depend on a legacy kernel minidriver.
